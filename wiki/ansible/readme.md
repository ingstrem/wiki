# Пояснения к параметрам:

[defaults]:

inventory — путь к инвентарю (может быть относительным);

remote_user — пользователь для подключения к хостам;

private_key_file — путь к приватному SSH‑ключу;

host_key_checking — отключение проверки SSH‑ключей (удобно для тестов);

deprecation_warnings — скрыть предупреждения о устаревших функциях;

retry_files_enabled — отключение создания .retry файлов.

[ssh_connection]:

ssh_args — дополнительные аргументы SSH;

pipelining — ускорение выполнения задач за счёт уменьшения числа SSH‑соединений.

control_path — шаблон для файлов управления SSH‑соединениями.

[privilege_escalation]:

become — включение повышения привилегий (аналог sudo);

become_user — пользователь, под которым выполняются задачи с повышенными правами;

become_method — метод повышения привилегий (sudo, su и т. д.);

become_ask_pass — запрашивать пароль для sudo (если True);

## Проверка конфигурации

Чтобы убедиться, что Ansible использует нужный ansible.cfg, выполните:
`ansible-config view`

Эта команда выведет полный конфиг, который будет использован при запуске.

Чтобы увидеть, откуда берутся значения конкретных параметров:
`ansible-config dump --only-changed`

Команда покажет только те параметры, которые отличаются от значений по умолчанию, и укажет путь к файлу, где они заданы.
